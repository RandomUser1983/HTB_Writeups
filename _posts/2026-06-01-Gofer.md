## Review

A surprisingly well designed machine. The foothold requires chaining three separate ideas together: recognizing that the Apache `<Limit>` directive only restricts specific HTTP methods, knowing that the Gopher protocol can be used as a raw TCP pipe to reach internal services, and actually crafting a working SMTP session through a URL parameter.
None of these steps are obvious in isolation, which makes the moment they click together genuinely satisfying.

The privilege escalation is equally solid. The credential sniffing step is a good reminder that active machines are not static, and the `notes` binary wraps a PATH hijack behind a heap use-after-free.
No public CVEs, just misconfigurations and a custom vulnerable binary. Loved every step of it.

**Personal Rating:** ⭐⭐⭐⭐⭐ (5/5)

**Recommended for:** People comfortable with web enumeration who want to practice chaining unconventional techniques and get a taste of basic binary exploitation.

The Gopher protocol is the new cool thing I learned about. This is the description from Wikipedia:

_Gopher is a communication protocol designed for distributing, searching, and retrieving documents in Internet Protocol networks. The design of the Gopher protocol and user interface is menu-driven, and presented an alternative to the World Wide Web in its early stages, but ultimately fell into disfavor, yielding to Hypertext Transfer Protocol (HTTP)._

The important part is that this old protocol is basically a raw TCP pipe and don't include any application-layer overhead, meaning it can be pointed at any port to interact with whatever service is listening. For example I can try to connect to SSH.

```bash
curl -X POST "http://proxy.gofer.htb/index.php?url=gopher://2130706433:22"

# Result
<!-- Welcome to Gofer proxy -->
SSH-2.0-OpenSSH_8.4p1 Debian-5+deb11u1
Invalid SSH identification string.
```

It works!

`iVar2` equals 0 only when the string at `local_10 + 24` bytes is equal to "admin".
The vulnerability is that `local_10` is not reset to NULL after freeing the user. If I create a user, delete it, and then create a note with "admin" at the right position (bytes 25 to 29), the heap allocator will reuse the same memory block, so `local_10` will still point to that address, now containing the note data. When case 8 checks the role, it reads "admin" and grants access.
